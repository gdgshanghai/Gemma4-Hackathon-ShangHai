## 这是什么

**Madori（户型解读）** 是一个用本地 Gemma 4 多模态视觉模型读懂户型图（**floor plan / 平面图**）的工具。

你给它一张图——可能是房产中介挂出来的 **户型图**，也可能是你自己家的平面图（PNG / JPG / PDF 单页）——它会像建筑师一样把这张图**看懂**，然后用普通人（非建筑专业）能听懂的话，从几个专业「镜头（lens）」分别讲给你听：

- **结构 / 户型（structure）** — 有哪些房间、各自的尺寸、整体布局。
- **动线（circulation）** — 你在这个家里怎么走、怎么生活，哪里会堵、哪里绕路。
- **采光（light）** — 哪些房间能晒到太阳。**诚实第一**：如果图上没标朝向（东南西北），它会直接说「未知」，绝不瞎猜。
- **无障碍（accessibility）** — 门宽、台阶、卫生间 / 厕所的可达性。对老人 / 轮椅使用者来说，这个家好用吗？
- **生活漫游（daily-life walkthrough）** — 一段大白话的「居住漫游」：你从这里进门，客厅在……带你走一遍。
- **设计批评（critique）** — 一个优点、一个缺点（都带图上的证据）、一个具体可落地的改进建议。

除了文字解读，Madori 还会把这张**平面图**生成一个白色的 **3D「study model（白模 / massing）」**，让你拖一个滑块在「**平面 ⟷ 立体**」之间切换，**亲眼看到**这个家的体量和层次——而不是只能对着一张平面图想象。

**两种运行模式，你来选**：

- **本地隐私版**（默认）：Ollama + `gemma4:e4b`，全程本机，不上传任何云端，你的家不会离开你的电脑。
- **云端精度版**：调用 `gemma-4-31b`（仍是 Gemma 4，只是更大），房间抽取更全、命名更稳。几何由代码按抽取结构锁定校验，不靠模型臆测尺寸——需要更准布局时用。

两个模式共用同一套 `extract → lock → multi-lens` 编排（见下文）。**隐私优先用本地，精度优先用云端**——这正是边缘小模型与云端大模型分工的现实写照。

## 四个视图 · 把建筑师的眼睛交给你

**核心使命：把建筑师"看一眼图纸就读出的东西"，降维成普通人一眼就能看到的画面。** 不是给你一段段文字让你读，而是直接画在户型的 3D 平面上——切一下视图，专业分析就浮现在图上。

- **📖 解读** — 房间识别 + 五个专业「镜头」（动线 / 采光 / 无障碍 / 走读 / 批评）的大白话解读；点房间或镜头，模型里对应位置实时点亮。
- **☀ 采光** — 选一下北朝向，每个房间按它贴哪面外墙、朝哪个方位，**确定性算出采光等级**：南向暖橙（好）、东西黄（中）、北向蓝（弱）、内间灰（无窗）。建筑师"瞄一眼朝向判采光"，你一眼看到哪间晒得到太阳。**这是算出来的事实，转动北朝向会实时重算。**
- **🚶 动线** — 从玄关出发，一条路径线穿过各房间 + 到达顺序编号，一眼看清"进门后怎么走"。（示意走向，按房间位置推）
- **♿ 无障碍** — 标出对老人 / 轮椅的关注点：湿区（门宽待查）、玄关（高差）、过窄的房间。一眼看到这个家哪里可能不友好。（提示关注点，门宽 / 台阶需现场确认）

切换视图时相机**平滑过渡**、自动俯视压平成平面分区图；右侧面板可直接**输入实用面积**校准真实尺寸。

> **诚实分级**：采光是**确定性几何计算**（做实）；动线 / 无障碍是**示意 / 提示**（标注清楚，不冒充精确）。读不准的脏图会**自动降级**成外框 + 提示，绝不画一个骗你的精细模型。

### 诚实降级（边界情况处理）

![诚实降级：脏图自动退成外框 + 估算标注](web/assets/honest-downgrade.png)

> 喂一张**标注密集 / 拍照畸变**的脏图（几何置信度 `low`，铺满率 0.12）时，3D **不会**硬画一个骗你的精细模型——它自动退成白色外框 + 顶部"⚠ 几何为估算"警告，并标注"房间识别与多维解读不受影响"。**干净图 = 精确白模，脏图 = 诚实外框**，这是同一套置信度门控的两种输出。

## 为什么重要（社会价值）

这不是一个炫技玩具。它解决的是一个真实、普遍、且不公平的信息差。

**大多数普通人其实读不懂户型图。** 但偏偏就是对着这几张图，人们做出了人生中最大的居住决定——租房、买房。在房东和中介面前，不会读图的人天然处在信息劣势：图上写着什么、缺了什么、哪里有坑，他们看不出来。**Madori 想做的，是把一位建筑师的「读图能力」免费、私密地交到每个人手里。**

具体来说，它对这几类人尤其有用：

- **面对超高龄社会的家庭。** 日本正快速老龄化。**无障碍** 这个镜头能帮家庭在**实地看房之前**，就从图纸判断一个家对老人或残障家属是否安全、是否住得下去——门够不够宽、有没有台阶、厕所进得去吗。
- **远程做居住决定的人。** 因调动、留学、身在海外而**没法亲自到现场**看房的人——只能靠图纸下判断，Madori 帮他们把图纸读透。
- **请不起顾问的人。** 全本地 = 私密 + 免费。这份「读图能力」不该是付得起咨询费的人才有的特权。

## 可扩展性

Madori 的可扩展不是口号，是架构自带的三层伸缩：

1. **换图即用，零改代码** — `extract → lock → multi-lens` 与具体户型无关：Gemma 4 同时读图里的线条（视觉）和房间名/尺寸（图内文字），所以**任何户型图、任何语言标注**都走同一条 pipeline，没有一行"针对某张图"的硬编码。
2. **隐私 ⟷ 精度，一个变量伸缩** — 同一套 Gemma 4 编排，靠 `MADORI_MODEL` 一个环境变量在本地 `e4b`（离线/隐私/免费）与云端 `31b`（高精度/高吞吐）之间切换，业务逻辑不动。隐私优先的个人用本地，要批量精度的接云端。
3. **真实建筑覆盖全日本** — Leg B 的几何来自 PLATEAU 开放数据 + 确定性网格码（JIS X 0410）：任意坐标 → 自动定位取楼，**不需要为每栋楼单独建模**，天然覆盖日本全国。

部署上：pipeline 无状态，云端模式可水平扩展；本地模式跑在消费级 Mac（M4 Pro 24GB）即可，单机即产品。

## 怎么用

**前置条件**：本机已安装 [Ollama](https://ollama.com)，并拉好 Gemma 4 多模态模型。

```bash
# 1. 启动 Ollama 服务
ollama serve

# 2. 拉取 Gemma 4 多模态模型（e4b 版，适配本地显存）
ollama pull gemma4:e4b
```

**读一张户型图**：

```bash
# 传入一张 户型图（PNG / JPG / PDF 单页）
python3 pipeline/plan_read.py samples/floorplan.png
```

脚本会：

1. 在终端打印各镜头的解读（结构 / 动线 / 采光 / 无障碍 / 生活漫游 / 设计批评）；
2. 自动生成并打开一份 **HTML 报告**，把所有镜头的解读排版在一起，方便回看。

**看 3D 白模**：

3D massing（平面 ⟷ 立体滑块）是一个网页，在浏览器里打开即可：

```bash
# 用任意静态服务器起 web/ 目录
python3 -m http.server 8000 --directory web
# 浏览器访问 http://localhost:8000
```

拖动 **平面 ⟷ 立体** 滑块，平面图会立起来变成白色体块模型，房间会标上从图纸里读出的名字。

**（可选）云端精度模式** — 要更全的房间抽取 + 更准布局时，用云端大 Gemma 4（几何仍由代码锁定校验）：

```bash
echo "GOOGLE_AI_KEY=你的key" > .env.local                                      # Google AI Studio key（gitignored，不进库）
python3 pipeline/plan_read.py samples/madorizu_1f.png                            # 本地 e4b：拿五镜头文字解读
MADORI_MODEL=gemma-4-31b-it python3 pipeline/madori3.py samples/madorizu_1f.png  # 云端 31b：抽精确几何
python3 pipeline/precise_to_reading.py                                          # 合并 → 精度版 web/madori.html
```

## Gemma 4 如何被用

这个项目的核心能力，**就是 Gemma 4 的视觉**——它读那张图，这件事本身就是整个产品。没有它能看懂图，一切都不成立。这是一个把多模态当主角、而不是当点缀的项目（**赛道 B / Multimodal**）。

但「能看图」不等于「读得准、读得稳」。一次性把整张图丢给模型让它讲六个镜头，模型很容易**漂移**——同一个房间，讲动线时叫它「主卧」，讲采光时又叫它「卧室 A」，前后对不上，整份解读就不可信了。

所以这里做了一个刻意的工程编排——**extract → lock → multi-lens（抽取 → 锁定 → 多镜头）**：

1. **Extract（抽取一次）**：先只让 Gemma 4 做一件事——从图里把**结构**抽出来：有哪些房间、各自的尺寸。
2. **Lock（锁定为上下文）**：把这份抽取结果**锁定**成一份固定的上下文（房间清单 + 尺寸），后续不再变。
3. **Multi-lens（带着锁定上下文跑每个镜头）**：之后每一个镜头（动线 / 采光 / 无障碍 / 生活漫游 / 设计批评）都**带着同一份锁定上下文**去跑。于是所有镜头用的是**同一套房间名**，不会再各讲各的。

**分工很清楚**：每一个「判断」都由 Gemma 4 做（看图、解读、批评）；而**状态管理、镜头循环、失败重试**这些由代码来编排。LLM 负责理解，代码负责让流程稳定一致。

正是这套 **extract → lock → multi-lens** 编排，让 Madori 给出的是一份**前后一致、可被追问的诚实解读**，而不是一次性 prompt 拍脑袋的输出。

## 诚实边界

这份诚实本身，是产品的一部分。请认真读这一节。

- **它是「设计通识 / design-literate」级别的解读，不是专业认证。** Madori 给的是「帮你看懂」的辅助理解，**不等于**持证结构工程师的结构判断，也**不等于**正式的无障碍合规审计。
  ⚠️ **凡涉及法律、安全、结构的决定，请务必咨询持证专业人士。** Madori 是理解的起点，不是签字的依据。
- **朝向未标 → 采光说「未知」。** 当图上没有标注东南西北时，采光分析能给的信息有限。这种情况下 AI 会明确说「未知」，而**不会编一个听起来合理的朝向糊弄你**。
- **房间坐标是近似值。** 从图里抽出的房间位置 / 尺寸是估算的，所以 **3D 白模和房间标注是「示意」级别**，不是测绘级精度。别拿它去算施工或下定金。
- **最适合干净、带房间文字名的挂牌式 户型图。** 对清爽、写明"客厅/卧室/厨房"的房产户型图读得最好（模型靠读这些字认房间）。**已知射程外**（结果不可靠，会触发降级或读错）：① 标注密集的彩色图（面积㎡数字易被当坐标）；② 深底 CAD 技术图（密集线 + 家具符号 + 常无房名）；③ 完全没有房间文字名的图。这类图现阶段建议不要依赖其几何输出。

## 真实建筑模式（腿 B）

上面是「**户型图 → 解读**」。Madori 还有第二条腿：「**真实建筑 → 真实白模 + 真实解读**」。

核心反转：**不从一张照片重建 3D**（单图重建只能给个包围盒，丢掉所有形态——实测过）。而是 **照片/地址 → 定位 → 从已有的真实 3D 数据库取这栋楼的几何**。几何交给真正有几何的地方，Gemma 干它最强的：识别 + 理解。

```bash
# 1) 定位：从照片 EXIF GPS 取坐标（截图无 GPS 时手填）
python3 pipeline/locate.py photo.jpg              # 或 --lat 35.6638 --lng 139.5872

# 2) 自动选 mesh：坐标 → 日本标准网格码（确定性，JIS X 0410）→ 取 PLATEAU CityGML
python3 pipeline/geo.py --lat 35.6638 --lng 139.5872

# 3) 真实白模：CityGML 的 footprint + 高度挤出（全本地，断网可渲，无 key 无云）
python3 pipeline/plateau_parse.py <那块.gml>      # 生成并打开 web/plateau_view.html

# 4) 真实采光：有坐标 = 有朝向 → 确定性算（不靠猜）
python3 pipeline/real_read.py <那块.gml>          # 立面朝向分布 / 西晒 / 太阳高度角

# 5) Gemma 定性解读真实建筑照片（体量 / 材质 / 文脉 / 批评，可叠加真实采光）
python3 pipeline/building_read.py photo.jpg --lat 35.6638 --lng 139.5872
```

**腿 B 顺带解决腿 A 的硬伤**：户型图没标朝向 → 采光只能说「未知」；接入真实坐标 → **采光变成可算的事实**（这是质变）。

**数据源**：[PLATEAU](https://www.mlit.go.jp/plateau/)（国土交通省日本全国 3D 都市模型，CityGML 开放数据，CC BY 4.0）。下载一次即可**完全离线**，无 API key、无云。LOD1 = 挤出体块（白模本色），市中心有 LOD2（带屋顶）。

> ⚠️ 腿 B 诚实边界：真实白模是 LOD1 体块（非测绘级、无外立面细节）；通用城市（非已缓存区）需走 PLATEAU 数据目录获取对应数据；采光是确定性几何 + 太阳路径计算，是「方位与日照角度」的事实，不替代专业日照分析。

## 项目结构

```
madori/
├── pipeline/
│   ├── plan_read.py        # 腿A：户型图 extract→lock→5镜头 + 生成 reading.html / 白模
│   ├── locate.py           # 腿B：照片 EXIF GPS → lat/lng（定位）
│   ├── geo.py              # 腿B：lat/lng → 日本网格码 → 取 PLATEAU CityGML（确定性）
│   ├── plateau_parse.py    # 腿B：CityGML footprint+高度 → web/plateau_view.html 白模
│   ├── real_read.py        # 腿B：坐标+几何 → 真实朝向采光（确定性计算）
│   └── building_read.py    # 腿B：真实建筑照片 → Gemma 定性解读 + 叠加采光
├── web/
│   ├── index.html          # 腿A 3D 白模：平面 ⟷ 立体 滑块
│   ├── massing.template.html  # 腿A 白模模板（footprint 挤出）
│   ├── plateau.template.html  # 腿B 真实白模模板（CityGML 挤出）
│   ├── plateau_view.html      # 腿B 生成的真实建筑白模（示例：东京 20 栋）
│   └── real3d.html         # 腿B 流式 3D Tiles viewer（Google/PLATEAU，联网档）
├── samples/
│   └── floorplan.png       # 示例 户型图
└── README.md
```

- **`pipeline/`** — Python 编排层。本地 `gemma4:e4b` 调用、extract→lock→multi-lens 状态/重试、CityGML 解析、确定性采光、HTML 生成。
- **`web/`** — 纯前端白模 viewer（全局 three.js）：腿 A 户型挤出、腿 B 真实建筑挤出，均可拖拽旋转、平面 ⟷ 立体。
- **`samples/`** — 示例数据。
