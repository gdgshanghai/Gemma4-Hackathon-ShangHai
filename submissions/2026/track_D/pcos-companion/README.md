## 一句话

> PCOS 是一种需要**长期管理**的内分泌状况，影响中国约 **1.7 亿**女性。
> 她们面对的不只是疾病，更是两个长期被忽视的空白——
> **情绪支持的空白** 与 **就医信息的不对等**。
>
> 我们用 **Gemma 4** 做了一个「不诊断、只陪伴」的 AI 伴侣「小暖」，
> 并把所有**不能交给大模型自由发挥**的医疗动作，下沉为**确定性函数**，
> 由模型通过 **原生函数调用** 来编排。

---

## ✨ 为什么符合技术评分标准

| 评分维度 | 本项目的做法 |
|---|---|
| **架构清晰、模块化** | `gemma`（推理/编排/多模态）· `tools`（函数实现）· `safety`（护栏）· `privacy`（数据治理）四层解耦 |
| **深度利用原生函数调用** | 7 个工具以 OpenAI 兼容 `tools` schema 下发，由 Gemma 4 **结构化返回 `tool_calls`** 并多轮编排，**而非把工具塞进 prompt 做字符串匹配** |
| **多模态** | Gemma 4 26B MoE 解析化验单 / B 超报告图片，抽取结构化指标 |
| **端侧部署** | 默认 Gemma 4 4B（Q4 量化）本地推理，敏感对话**不出设备** |
| **一键启动 / 工程化** | `docker compose up` 或 `bash run.sh` 一键拉起；`pytest` 全绿 |

### 核心设计：把「危险动作」从模型手里拿走

风险评估、危机识别、就诊清单生成等动作**绝不**交给模型自由生成，而是写成**确定性函数**：

- 模型负责**理解与共情**，函数负责**判断与执行**；
- 模型**永远不会**自己说出「你得了 PCOS」——诊断不是它的职责；
- 一旦识别到自伤/危机关键词，`safety` 层**强制**触发危机干预流程，模型无法绕过。

> 这正是预览里对话中那几张 `✦ 小暖调用了…` 卡片背后的真实机制——
> **每一次函数调用，都是一次"模型不替你做主"的设计。**

## 🚀 一键启动

```bash
# 方式一：Docker（推荐）
docker compose up

# 方式二：本地
pip install -r requirements.txt
bash run.sh            # 启动 FastAPI 服务，默认 :8000

# 无 GPU 也能跑：确定性路径演示（含危机干预、就诊小抄）
python demo_local.py
```

服务接口：`POST /chat`（对话+函数编排）· `POST /privacy/erase`（一键删除全部数据）· `GET /healthz`

> 端侧推理对接 Ollama / llama.cpp，详见 [`edge/README.md`](./edge/README.md)，
> 设置 `GEMMA_EDGE_ENDPOINT=http://127.0.0.1:11434/v1` 即可，代码无需改动。

## 🔒 隐私与合规（Track D 必备）

- **端侧优先**：默认对话与函数调用全部在本地完成，敏感数据不出设备；
- **可删除**：`/privacy/erase` 一键清除全部用户数据，openid 仅以假名化形式留存；
- **知识可溯源**：健康信息均来自公开诊疗指南，知识库逐条标注来源；
- **不做诊断**：产品全程提供信息与陪伴，明确不替代医生，并在危机时引导就医与援助热线。

详见 [`PCOS伴侣_数据合规与隐私保护.docx`](./PCOS伴侣_数据合规与隐私保护.docx)。
